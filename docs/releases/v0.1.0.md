# Quota to Cash v0.1.0 — public preview

**Release notes · October 20, 2026.** [Quota to Cash](https://github.com/VictoR0213/quota-to-cash) explores turning spare AI coding capacity into useful, tested Apify tools and recording what they actually earn. QuotaForge remains the local workbench's application name. Use the [v0.1.0 release page](https://github.com/VictoR0213/quota-to-cash/releases/tag/v0.1.0) for the tagged source, downloadable source package and checksum.

Put spare AI coding capacity to work. Build, verify and publish small tools, then measure actual costs and receipts.

QuotaForge is a local open-source workbench for one bounded tool family: JSON record normalization. It turns a brief and independent fixtures into a declarative specification, checks the result with a trusted runtime and packages it for the operator's own Apify account.

## Included in this preview

- A loopback dashboard and Node.js CLI sharing local project state.
- A deterministic example that runs without an AI account, cloud token or npm dependency installation.
- Codex and Claude Code adapters using the operator's official local CLI authentication.
- ToolSpec validation and an allowlisted runtime for mappings, field transformations, deduplication and sorting. Model output is not executed as arbitrary JavaScript.
- Independent acceptance fixtures, generated Actor source, linked output metadata and a typed dataset schema.
- Separate, explicitly confirmed Apify deployment, exact-build cloud fixture checks and public publication with a pinned checked build.
- Owner-visible run-cost sync and a manual USD ledger that separates pending amounts, net receipts and additional expenses.
- MIT licensing, contribution and security guidance, example fixtures and a Windows/Linux × Node 22/24 CI configuration.
- Isolated deterministic demo checks and a reproducible source-only ZIP packager with an explicit file allowlist, per-file SHA-256 manifest and archive checksum.
- Local-calendar ledger validation, with regression checks at Singapore and Los Angeles date boundaries.

## Start locally

Install Node.js 22 or later, open a terminal in the source directory and run:

~~~sh
node --run test
node --run demo:check
node --run demo
node --run start
~~~

Open **http://127.0.0.1:4317**. The demo makes no model or cloud calls and does not simulate income. Follow the [public-preview checklist](../PUBLIC_PREVIEW.md) for isolated state, fresh-copy verification, source review and a recording procedure.

`node --run preview:check` verifies reproducible packaging and checks the extracted source. `node --run preview:pack` prepares the ZIP and checksum locally; it does not publish a release.

## Known limits

This is a personal local prototype, not a shared hosted service. Provider CLI restrictions and specification validation are not an operating-system sandbox. The local application has no npm runtime dependencies; generated Actors have separate cloud packaging and platform requirements.

Live results describe the dated environment and cases above. They do not prove that every account, provider release or input will work. Cloud acceptance checks one nonempty fixture rather than exhaustive production behavior. Claude Code and unassisted setup by a new external operator remain to be verified.

The workbench does not read remaining subscription quota, configure paid Actor pricing, automate customer acquisition or reconcile a bank account. Owner-visible run usage is a limited cost view. A manual ledger entry does not independently establish payment, and a public Actor does not establish demand or profit.
